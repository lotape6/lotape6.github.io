Dive 04-AMakefiles → Bazel

Why move a machine's software off Make

A Makefile describes how to build: recipes, include paths, link lines. What it does not describe is what depends on what. Over years, a large C/C++ tree accumulates include paths that reach into other components, libraries that link because they always have, and two copies of the same symbol that only one linker order resolves. The build works, but nobody can prove why, and a full rebuild is the only safe one.

Bazel inverts that. Every target declares its sources and its dependencies, and nothing else is visible to it. Hidden includes fail to compile. Circular dependencies fail to analyse. Duplicated symbols stop hiding behind link order. Once the graph is explicit it is also a DAG, so the build becomes incremental, cacheable and reproducible: the same inputs give the same outputs, on a laptop or a build farm.

My part was the unglamorous half: assessing the debt first (cycles, duplicated symbols, declarations that disagreed with reality), then migrating large lithography-machine components target by target, and writing the automation and verification tooling that kept the migration honest. The toy below shows the shape of the change, not ASML's code.

BeforeMakefile
# implicit: where does stage_ctl.h come from?
CXXFLAGS += -I../common -I../../metrology/include
LDLIBS   += -lmetrology -lcommon -lstage

all: stage_ctl

stage_ctl: stage_ctl.o servo.o
	$(CXX) $^ $(LDLIBS) -o $@

%.o: %.cpp
	$(CXX) $(CXXFLAGS) -c $< -o $@

# metrology/Makefile links -lstage back → cycle
AfterBUILD.bazel
# explicit: every input is a label
cc_library(
    name = "servo",
    srcs = ["servo.cpp"],
    hdrs = ["servo.h"],
    deps = ["//common:math"],
)

cc_binary(
    name = "stage_ctl",
    srcs = ["stage_ctl.cpp"],
    deps = [
        ":servo",
        "//metrology:interface",  # not //metrology:all
    ],
)
# a dep back from //metrology to :servo is a build error

What an EUV scanner does, as ASML describes it

All figures below are ASML's own public statements, quoted from asml.com. They are here to explain why the software's build infrastructure matters, not as claims about my work.

Light
13.5 nm extreme ultraviolet, made by hitting tin droplets with a laser to form a plasma at about 500,000 K; mirrors instead of lenses.
Source
Tin droplets travelling at 70 m/s, hit 50,000 times per second.
Wafer stage
Positioned to a quarter of a nanometre, corrected 20,000 times a second.
Parts
Around 100,000 per machine; shipping one takes 40 freight containers, three cargo planes and 20 trucks.
Software
Over 4,000 software engineers; embedded software of “millions of lines of code” steers and controls the machines.
Product
TWINSCAN NXE:3800E: high-volume manufacturing for 2 nm logic.
